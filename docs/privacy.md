# 개인정보 처리 결정 (v0.1 — BE #48)

이 서비스가 다루는 민감 데이터: **학점·자기소개서 원문·지원 결과**. 아래 결정은 명세서 F1-4(「llm api 사용시 개인정보 문제 고려 필요」)와 F4-4(「결과 데이터 활용은 사용자 동의 기반」)를 구현 규칙으로 옮긴 것이다. 코드가 이 문서와 어긋나면 코드가 틀린 것이다.

## 1. 외부(LLM API)로 나가는 데이터 범위

LLM 호출은 전부 `LlmGateway`(#35) 한 곳을 지난다. 현재 기본 구현은 **온프레미스 휴리스틱**이라 외부 전송이 없고, AI 서버(CareerCompass-AI)로 전환해도 아래 범위를 지킨다.

| 작업 | 외부로 나가는 것 | 나가지 않는 것 |
| --- | --- | --- |
| 공고 구조화 파싱 (#31) | 공고 제목·본문 (공개 텍스트) | 사용자 정보 일절 |
| 자소서 항목 분류 (#20) | (현재 온프레미스 처리 — LLM 전환 시) 문단 텍스트, **마스킹 후** | 이름·이메일·연락처·파일 원본 |
| 적합도 코멘트 (#33) | 매칭 키워드·미충족 조건 등 **집계 값** | 자소서 원문·프로필 원본 |
| 지원서 초안 생성 (#36) | 질문·경험 카드 요약·과거 자소서 발췌, **마스킹 후** | 이름·이메일·연락처·학번 |

- **마스킹 규칙**: `PrivacyMasker` 가 이메일·전화번호(01x)·주민등록번호 패턴을 `[이메일]`·`[전화번호]`·`[주민번호]` 로 치환한 뒤에만 `HttpLlmGateway` 가 전송한다. 테스트로 강제된다.
- 이름·학교·학번은 요청 페이로드 스키마 자체에 싣지 않는다 (게이트웨이 계약).
- 자소서 텍스트 추출·OCR 은 온프레미스 라이브러리(pdfbox·poi)만 쓴다 — 최종보고서 4.4.1 PII 경계.

## 2. 동의 (모델 개선 활용)

- `PUT /users/me/consent {modelImprovement}` 로 저장(`user_consent` 테이블). 기본값 **false**.
- 동의한 사용자의 `pass` 결과 데이터만 적합도 모델 개선·로드맵 senior 코호트 집계에 쓴다.
- 철회는 같은 엔드포인트로 즉시 반영 — 이후 집계에서 제외된다.
- FE 는 온보딩 또는 결과 입력 시점에 동의 UI 를 노출한다 (FE 이슈로 전달 필요).

## 3. 보관 기간·삭제 범위

| 데이터 | 보관·삭제 |
| --- | --- |
| 과거 지원서 파일 | 사용자가 삭제하면 **스토리지 파일까지 즉시 삭제** (구현·테스트 완료) |
| 지원 이력·지원서 | 사용자가 이력을 삭제하면 항목·버전까지 함께 삭제 |
| 알림 | 90일 후 자동 삭제 (일 배치) |
| refresh token | 만료(14일)·로그아웃·재사용 탐지 시 폐기 |
| 회원 탈퇴 | 탈퇴 API 는 미구현(스펙에 없음) — 구현 시 users soft delete + 소유 데이터(파일 포함) 하드 삭제로 정의한다. **졸업프로젝트 II 과제로 명시** |

## 4. 로그 마스킹

- Authorization 헤더·요청 본문은 로깅하지 않는다 (`RequestLoggingFilter`).
- FCM 토큰은 앞 8자만 로그에 남는다. refresh token 은 해시만 DB 에 저장, 원문은 어디에도 안 남는다.
- LLM 요청 페이로드는 로그로 남기지 않는다 — 사용량(usage)·경로만 기록.

## 5. 미결·후속

- Bedrock(또는 AI 서버) 인리전·no-training 계약 확인은 CareerCompass-AI 쪽 과제 (AI#1).
- 개인정보처리방침 문구(수탁자 고지·DPA)는 배포(#7) 전 작성.
